# GFireUI v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a SvelteKit SPA ops console (light/dark, RBAC-aware screens, polled charts) that talks only to `gfireui-backend`.

**Architecture:** Static SPA/CSR. Auth = JWT in memory + `localStorage` (v0.1). All API calls to backend base URL. No direct GFire access. CSS variables for light/dark; theme packs post-v1.

**Tech Stack:** SvelteKit (latest stable Svelte 5), TypeScript, Vite static adapter, CSS variables (no heavy UI kit required), chart lib chosen in Task 6 (`uPlot` or LayerCake — pick one and stick).

**Spec:** [platform design](../specs/2026-08-06-gfireui-platform-design.md)  
**Depends on:** [gfireui-backend v0.1 plan](https://github.com/hrodrig/gfireui-backend/blob/develop/docs/superpowers/plans/2026-08-06-gfireui-backend-v0.1.md) Tasks 6+ (login) for real integration; mock fetch allowed for early UI tasks.

## Global Constraints

- English only in code, UI strings, commits, docs.
- Branch `develop`.
- Whitelist `.gitignore` — whitelist new root config files when scaffolding adds them.
- No employer product names in repo.
- Roles: Administrator | Operator | Auditor | Guest — hide controls in UI; never treat UI checks as security.
- Palette tokens from design §10 (dark + light).
- Charts: browser poll 2–5s — no SSE/WS in v0.1.
- OAuth2 UI deferred (post-v0.1).
